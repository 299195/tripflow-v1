# TripFlow V1 需求与功能说明

## 1. 版本定位

TripFlow V1 是一个面向个人用户的中文旅行规划网页端：用户通过对话生成目的地攻略，搜索并收藏地点，创建可解释的单日行程，并在地点不可用或路线失败时获得明确的替代建议。

V1 的核心价值是把自然语言意图、真实地点数据、用户偏好、行程约束和可审计的规划结果连接起来，而不是只生成一段旅游文案。

## 2. 用户流程

### 首页：对话生成攻略

用户输入目的地、日期和偏好，系统调用 `POST /api/v1/guides/draft`，返回结构化摘要、候选地点、建议顺序和来源说明。Qwen 可用时负责建议和解释；不可用时使用确定性模板与地点搜索结果。草稿必须由用户确认后才保存为行程。

### 探索：搜索与收藏地点

用户按城市、关键词、分类或当前位置搜索景点、美食、咖啡、娱乐和住宿。美团地图授权可用时优先使用美团，未配置、鉴权失败或服务异常时回退高德，并展示来源与 warning。用户可以打开地点详情、收藏地点或加入规划。

### 我的：用户信息、收藏与行程

V1 使用 `local-traveler` 作为本地匿名用户标识，不实现登录注册。用户可以查看个人摘要、收藏地点、已保存行程、当前行程版本和历史版本。

## 3. 功能需求

### F1 对话式攻略草稿

- 支持目的地、日期、天数、兴趣、预算和同行者等输入。
- 返回结构化 JSON，而不是只能阅读的长文本。
- 返回候选 POI、建议理由、摘要和数据来源/风险说明。
- 对 Qwen 超时、异常、空响应和非法 JSON 提供 fallback。
- AI 是建议层，不是事实源和约束执行器。

### F2 地点搜索与详情

- 支持关键词搜索和附近搜索。
- 支持景点、美食、咖啡、娱乐和住宿分类。
- 统一字段：`id`、`name`、`category`、`address`、`location`、`distance`、`provider`、`image_url`、`description`。
- 未由外部服务提供的字段保持 `null`，不得猜测填充。
- 支持地点保存与收藏。

### F3 收藏与个人页

- 收藏操作幂等。
- 收藏保留地点快照、来源和用户备注。
- 个人页展示收藏和行程摘要。

### F4 行程与约束

- 支持创建旅行、生成行程、编辑行程、查看版本和恢复版本。
- 规划器处理日期、时间窗口、停留时长、固定预约、地点坐标和地点间移动时间。
- 单次规划最多安排 8 个停靠点。
- 对无法满足的预约、时间或路线约束返回结构化冲突与替换建议。

### F5 解释与执行事件

- 行程结果说明关键约束、未满足项和建议动作。
- 支持记录开始、到达、完成、跳过和备注等执行事件。
- V1 的执行事件是基础日志和后续扩展接口，不承诺自动实时重规划。

### F6 降级和错误

- 地图服务错误、未知字段和空结果必须被识别并记录。
- 美团失败回退高德；高德失败时返回本地结果或明确错误。
- Qwen 不可用时仍能完成基本攻略流程。
- fallback 必须在响应的 `warnings` 或 `provider` 中体现。

## 4. V1 范围外

- 登录、注册、多用户权限、团队协作和社交分享。
- 酒店/餐厅/门票真实预订、支付和订单履约。
- 未经供应商提供的图片、评分、价格、营业状态自动补全。
- 基于 GPS 的后台监控、自动延误检测和全自动动态重规划。
- 多城市多日的全局最优求解。
- 多 Agent 协作、自进化、在线学习和长期记忆。

## 5. 验收标准

- 首页、探索、我的三类页面可以在中文环境下直接使用。
- 首页完成“输入偏好 → 生成草稿 → 查看候选地点 → 收藏/保存”闭环。
- 探索页完成“搜索 → 查看详情 → 收藏”闭环。
- 我的页面展示收藏和已保存行程。
- 未配置 Qwen 时仍可生成基础攻略。
- `python -m pytest -q` 全部通过。
- `python eval/run_eval.py` 能执行 V1 场景评测。
- `GET /health` 返回 `status=ok`。
- 真实密钥不出现在源码、文档、测试数据和 Git 历史中。

## 6. 已知限制

- V1 是单用户、单城市、单次旅行/单日规划优先版本。
- Qwen 是可选建议层，真实调用依赖本地配置和网络。
- 美团公共地图搜索字段不稳定提供图片和简介，缺失字段保持为空。
- 高德适配器提供真实 POI/路线能力，但当前规划主链路仍以确定性估算为核心，不能宣称已完成真实交通路线规划。
- 领域模型预留版本和事件边界，但自动重规划、自进化和多 Agent 尚未实现。
